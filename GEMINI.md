# 🛡️ AI Cyber-Patch Sentinel — Agentic Swarm (Phase 1)

This directory contains the Agentic Swarm implementation, now upgraded to a **Dual-Agent Privacy-Safe Swarm** for vulnerability remediation.

## 🚀 Phase 1 Evolution

The swarm has evolved from a single-agent ReAct loop to a dual-agent architecture that balances technical intelligence with data privacy.

### Core Components

| Component | File | Description |
| :--- | :--- | :--- |
| **Agent Coordinator** | `agent_coordinator.py` | The "Swarm Brain". Orchestrates the ReAct loop and handles the Local-to-Cloud anonymization bridge. |
| **MCP Sentinel Server** | `mcp_sentinel_server.py` | The "Tool Backbone". Provides SSH-native execution across multiple OS families. |
| **Swarm Dashboard** | `swarm_ui.py` | A `rich`-based terminal UI providing real-time visibility into both agents' reasoning and pipeline status. |
| **Cloud Advisor** | Virtual (via litellm) | Uses `gpt-4o` for high-level technical intelligence without seeing sensitive data. |
| **Orchestrator** | Virtual (via litellm) | Uses `ollama/gemma4:e4b` (default) for local reasoning and tool execution. |

## 🏗️ Architecture & Workflow

### 1. Privacy-Safe Anonymization
All communication with the Cloud Advisor passes through an **Anonymization Layer** in `agent_coordinator.py` that redacts:
*   IPv4 addresses (`[REDACTED_IP]`)
*   SSH usernames and emails (`[REDACTED_EMAIL]`)

### 2. Cross-Platform Support
The system now supports multiple operating systems and package managers:
*   **OS Families**: Debian/Ubuntu, RHEL/CentOS/Fedora, Arch, SUSE, Alpine, macOS, and Windows.
*   **Package Managers**: `apt`, `dnf`, `yum`, `pacman`, `apk`, `zypper`, `brew`, `choco`, `winget`.

### 3. Integrated Toolset (MCP)
*   **Discovery**: `detect_os` (OS/Kernel/PkgMgr detection).
*   **Audit**: `scan_target` (Vulnerability scanning via native package managers).
*   **Usage Analysis**: `check_package_usage` (Probes processes via `lsof`, systemd services, and binaries).
*   **Safety Net**: `create_snapshot` (Tar-based on Linux, Restore Point on Windows) and `create_aws_snapshot` (AWS EBS).
*   **Remediation**: `deploy_patch` (Surgical version-specific upgrades).
*   **Verification**: `run_custom_test` (Bash-based validation tests).
*   **Rollback**: `rollback_aws_snapshot` (EBS-based instance restoration).

### 4. Verification Pipeline
1.  **Detection**: OS and Package Manager identification.
2.  **Intelligence**: Consultation with Cloud Advisor for stable versions and usage patterns.
3.  **Snapshot**: Creation of pre-patch safety net (Local or AWS).
4.  **Patching**: Surgical deployment of the verified package version.
5.  **Validation**: Execution of 3 custom bash tests generated by the Cloud Advisor.
6.  **Rollback**: Automatic revert if any test fails, followed by Root Cause Analysis (RCA).

## 🛠️ Building and Running

### Running the Swarm
The system uses `.env` for configuration. The `agent_coordinator.py` automatically spawns the MCP server.

```bash
# Ensure .env is populated with:
# TARGET_HOST, TARGET_USER, TARGET_PASSWORD
# LLM_MODEL (default: ollama/gemma4:e4b)
# OPENAI_API_KEY (for intelligence)
# AWS_ACCESS_KEY_ID/SECRET (for snapshots)

python agent_coordinator.py
```

## 📜 Development Conventions

- **Tool Decoration**: Decorate new remote capabilities with `@mcp.tool()`.
- **State Machine**: The UI tracks phases: `IDLE` → `DETECTING` → `SCANNING` → `SCANNED` → `SNAPSHOTTING` → `SNAPSHOT_READY` → `PATCHING` → `PATCHED` → `VERIFIED`.
- **Anonymization Layer**: Update `CloudAdvisor._anonymize` if new sensitive patterns emerge.
- **Logging**: Swarm events are logged to `swarm_events.log`, MCP logs to `sentinel_mcp.log`.
- **Error Handling**: The agent STOPs on failure. **Never proceed on SSH or AWS errors.*
